# HomeTube 리모컨 연결 보안

## 연결 흐름

- HomeTube main process가 로컬 HTTP 페이지와 WebSocket 서버를 실행한다. 앱 설정에서 리모컨 서버를 켠 경우 앱 재시작 뒤에도 등록된 휴대폰의 재연결을 받을 수 있다.
- 서버는 LAN 연결을 위해 전체 인터페이스에 바인딩한다. HTTP와 WebSocket 요청은 사설, 루프백, 링크 로컬 주소만 처리하고, Host와 WebSocket Origin을 검사한다. 라우터 포트 포워딩은 만들지 않는다. Windows 방화벽은 개인 네트워크만 허용해야 한다.
- QR 링크의 토큰은 URL fragment에 들어가므로 최초 HTTP 페이지 요청에는 포함되지 않는다. 페어링 토큰은 32바이트 난수이며 6자리 코드는 2분 동안 한 번 사용할 수 있다. 한 기기 등록 뒤 다음 기기를 위해 새 코드와 QR을 만든다.
- 각 휴대폰에는 별도 기기 ID와 32바이트 세션 토큰을 발급한다. HomeTube는 세션 토큰의 SHA-256 해시만 사용자 데이터 폴더에 저장한다. 기기 폐기 시 저장된 해시를 지우고 해당 WebSocket을 닫는다.
- 페어링 QR과 페어링 토큰은 YouTube Leanback 렌더러에 보내지 않는다. 페어링 QR은 별도의 context-isolated, sandboxed Electron 창에만 표시한다. Leanback 설정 렌더러에는 연결 상태, 기기 목록, 페어링 비밀이 없는 일반 리모컨 페이지 QR만 전달한다.
- 설정 화면에 표시하는 `리모컨 페이지` QR에는 일반 리모컨 페이지 주소만 들어가며 페어링 토큰은 포함되지 않는다. 이미 등록되어 브라우저에 세션 토큰이 저장된 휴대폰에서 빠르게 페이지를 열 때 사용한다.

## 보안 한계

- 현재 연결은 `http://`와 `ws://`를 사용하며 LAN 트래픽을 암호화하지 않는다. 인증 토큰은 암호화가 아니다. 같은 네트워크에서 트래픽을 감시할 수 있는 공격자는 페어링 중 세션 토큰을 읽을 수 있다.
- 휴대폰 브라우저는 재연결을 위해 세션 토큰을 `localStorage`에 보관한다. 브라우저의 사이트 데이터 삭제 또는 HomeTube에서 기기 폐기를 사용해 연결을 끊을 수 있다. 이 저장소는 OS 보호 저장소처럼 하드웨어 보호를 보장하지 않는다.
- 따라서 신뢰할 수 있는 개인 Wi-Fi에서만 사용하고, Windows 방화벽에서 개인 네트워크만 허용한다. 공개 Wi-Fi에서는 사용하지 않는다.
- HTTPS/WSS는 아직 적용하지 않았다. 로컬 IP에 유효한 인증서를 발급하고 Android 및 iOS 브라우저에서 신뢰시키는 인증서 배포 방식이 정해지기 전까지 암호화되었다고 표시하지 않는다.
- Android Chrome에서는 리모컨 페이지를 연 뒤 메뉴(⋮)의 `홈 화면에 추가`를 사용해 바로가기를 만들 수 있다. LAN 주소는 HTTP이므로 이 바로가기는 브라우저에서 여는 웹사이트 바로가기다.

## 메시지 제한

- 현재 프로토콜은 버전과 메시지 종류를 런타임에서 검증한다. 인증 전에는 `pair`, `resume`, `ping`만 허용하고, 인증 후에는 방향·선택·뒤로·홈, 재생, 이동, 음량 명령만 처리한다. 휴대폰 검색 입력 기능은 Leanback 검색과 안정적으로 연동되지 않아 제거했으며 TV의 Leanback 검색을 사용한다.
- WebSocket 메시지는 4 KiB, 인증되지 않은 연결은 15초, 연결당 잘못된 메시지는 누적 5회, IP당 분당 페어링 시도는 5회, 기기별 분당 리모컨 명령은 120회, 전체 WebSocket 연결과 등록 기기는 각각 8개로 제한한다.
